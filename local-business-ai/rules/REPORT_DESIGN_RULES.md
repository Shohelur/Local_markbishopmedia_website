## 1. The Separation Rule (Critical)
The Report Designer controls **presentation only**. It must not:
- Create new findings, recommendations, or statistics.
- Change, promote, or demote any Priority Engine ranking.
- Remove evidence-backed findings for aesthetic reasons.
- Invent competitor comparisons, logos, or booking URLs.
- Rewrite business facts.

**The Report Writer owns content. The Report Designer owns presentation.**

---

## 2. Visual-First Principle (Core Rule)
For every important finding, the designer must ask: **"Can this finding be understood faster with a visual?"**

If yes → visual comes first, then explanation.
If no → use the clearest editorial format available.

**PROHIBITED:** Beginning a finding section with several paragraphs of text when a visual representation is available and meaningful.

**REQUIRED:** Every visual must communicate a real business question. Examples:
- "How does our review volume compare to a nearby competitor?"
- "Which directories are we present on vs missing from?"
- "How many services do we list compared with the competition?"

Do not create a graph merely because a graph looks attractive. Every graph must earn its place.

---

## 3. Visual Selection Intelligence
Match the visual type to the story:

| Finding Type | Preferred Visual | Example |
|---|---|---|
| Review volume vs competitor | `bar_comparison` — side-by-side bars | Your 21 vs Competitor 520 |
| Service catalog gap | `metric_comparison` — large metric blocks | Your 8 vs Competitor 15 |
| Directory coverage | `qualitative_bars` or `coverage_table` | Claimed: Google, Yelp / Unclaimed: Healthgrades, Zocdoc |
| Profile completeness | `qualitative_bars` — status segments | Strong Foundation / Opportunity / Needs Attention |
| Rating comparison | `metric_comparison` | Your 5.0 ★ vs Competitor 4.8 ★ |
| General qualitative finding | Editorial layout | Clean callout, no fake chart |

**PROHIBITED:** Using a single chart type for every section. Use layout variety.

---

## 4. Never Invent Numerical Data
- **PROHIBITED:** Fake percentages (e.g., "72% complete", "91% Visibility")
- **PROHIBITED:** Invented health scores (e.g., "84/100 SEO Health")
- **PROHIBITED:** Fabricated revenue impact estimates
- **PROHIBITED:** Bar charts where bar widths represent invented proportions

Qualitative status indicators (e.g., diagnostic segment bars) are allowed. They must be labeled as qualitative status signals, not percentages or scores.

---

## 5. Qualitative Visuals Are Allowed
When numerical data is insufficient, use qualitative status indicators:

```
Strong Foundation  ████████████  
Opportunity        ████████      
Needs Attention    ████          
```

These communicate relative status without inventing percentages. They must never be labeled as percentages unless actual percentages exist in validated data.

---

## 6. Layout Variety Rule
Do NOT render every section as an identical card.

Approved layout types:
- Full-width hero editorial section
- 2-column grid (text + visual)
- 3-column metric comparison blocks
- Horizontal comparison bars (actual values labeled)
- Qualitative diagnostic segment bars
- Coverage table with status icons
- Numbered action timeline
- Large metric stat anchor (e.g., `5.0 ★`)
- Expandable evidence drawer ("See More Details")
- Side-by-side competitor profile cards

**PROHIBITED:** Card → Card → Card → Card throughout the entire report.

---

## 7. Readability Over Page Count
- **Never reduce font size merely to fit content into fewer pages.**
- **Never compress or drop meaningful findings.**
- Report length is content-driven.
- Body typography: comfortable **13.5px / 1.6 line-height** (web) / **11–12pt equivalent** (PDF).
- Section headings: 24–26px. Display titles: 38–42px. Key Metrics: 36–48px.

---

## 8. Cover / Opening Section Rules
The opening must immediately establish:
- Brand identity (Local Growth Division · A Mark Bishop Media Company)
- Report title ("Local Business Visibility Report")
- Business name — visually most prominent
- Location / market
- Short personalized intro ("This report was prepared specifically for your business.")

---

## 9. Executive Glance Rule (Zero Flat Rows — 2x2 Matrix Required)
- **PROHIBITED:** Rendering the "Local Visibility at a Glance" section as flat, single-line horizontal stat rows or plain tables.
- **REQUIRED:** Must always render as an **interactive 2x2 Visual Diagnostic Matrix** with:
  1. SVG Circular Radial Gauges / Donut Meters (84px) with color-coded status arcs.
  2. Distinct pillar domain icons (`📍`, `🏢`, `⭐`, `🌐`).
  3. Evidence-backed metric chips (`21 Verified Reviews · 5.0★`, `8 Listed Services`).
  4. Status badges matching the color scheme.

---

## 10. Non-Technical Business Impact & Client Conversion Rule
- **Audience:** Non-technical local business owners (dentists, plumbers, contractors, clinic owners) who have limited time.
- **Language Standard:** Translate all technical findings into direct business revenue impacts (e.g. *"Missing directory presence means patients in your area searching for emergency appointments are being directed to competitors"* instead of *"NAP schema divergence identified"*).
- **Natural Solution Bridge:** Each priority must clearly show the actionable service capability from Mark Bishop Media / Local Growth Division that solves the problem.


**PROHIBITED:** Large empty decorative space at the top.
**PROHIBITED:** Generic software dashboard aesthetic.

The opening experience must communicate: *"This report was prepared specifically for your business."*

---

## 9. Section Sequence
Default sequence (omit sections with no content):
1. Cover / Introduction
2. Local Visibility at a Glance
3. What Is Working (Strengths)
4. Priority Finding Deep Dives (1 per finding)
5. Competitive Snapshot (conditional)
6. Additional Growth Opportunities (conditional)
7. Action Plan
8. CTA (Mark Bishop Media — single instance, end only)

---

## 10. Strengths Before Weaknesses
Strengths must appear before or alongside weaknesses. Never lead with a list of problems before acknowledging what the business has already built.

---

## 11. Progressive Disclosure ("See More") Rule
Every finding must support a collapsed default view and an expanded view:
- **Default:** Visual + What We Found + Why It Matters + Recommended Action
- **Expanded:** Additional evidence, specific named items, technical detail

Do not remove useful research solely to reduce visible length. Use progressive disclosure to preserve depth without overwhelming the initial view.

## 12. Color System (V4)
| Role | Token | Default Value |
|---|---|---|
| Primary | `primary` | `#0B192C` (Deep Slate / Navy) |
| Accent | `secondary` | `#D97706` (Warm Gold / Amber) |
| Very High Priority | `priority_very_high` | `#991B1B` (Restrained Crimson) |
| High Priority | `priority_high` | `#B45309` (Warm Amber) |
| Moderate Priority | `priority_moderate` | `#1D4ED8` (Royal Blue) |
| Low Priority | `priority_low` | `#475569` (Slate) |
| Strengths | `strength` | `#047857` (Emerald Green) |
| Opportunity | `opportunity` | `#0369A1` (Steel Blue) |
| Fonts | `font_display`, `font_primary` | Plus Jakarta Sans / Inter |
| Body Text Size | `font_size_body` | `13.5px` (web) / `13px` (PDF) |

Color use:
- Red → communicates attention, not panic
- Green → communicates strength
- Gold → brand emphasis or opportunity
- Blue → restrained — moderate priority or opportunity
- Avoid excessive gradients, shadows, and rounded cards

---

## 13. Typography Rules
- **No Negative Letter-Spacing:** `letter-spacing: 0; word-spacing: normal;` on all headings.
- **Fonts:** Plus Jakarta Sans for display/headings, Inter for body text.
- Preconnect to Google Fonts; synchronize via `document.fonts.ready`.
- Never fail an entire render due to a missing web font — fall back to `system-ui, sans-serif`.

---

## 14. CTA Rules
- **Single instance** at the very end.
- **PROHIBITED:** Repeating the CTA mid-report.
- **PROHIBITED:** Aggressive or fear-based sales language.
- The CTA must feel like a natural continuation of the research.
- Use `cta_extended` for Mark Bishop Media branding, contact details, and consultative copy.

---

## 15. Competitor Metrics Data Source Rule
- Use `competitive_snapshot.competitor_metrics` (structured object) for all chart data.
- **PROHIBITED:** Extracting numbers by regex-parsing the `observation` prose field.
- If `competitor_metrics` is absent, fall back to the `observation` prose only for display text — not for chart values.
