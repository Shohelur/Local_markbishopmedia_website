# Report Generation & Design Rules

## Core Philosophy
The final report should feel less like a technical SEO audit and more like a premium, human-researched local business growth assessment.

**Primary Audience:** Local business owner (non-technical)
**Secondary Audience:** Sales team

The report MUST answer, in order:
1. What is already working?
2. What is the biggest opportunity?
3. Where are opportunities being lost — and why does that matter to the business?
4. How do we compare with relevant competitors?
5. What should be done first?
6. What is the next step?

---

## The Visual-First Rule (Hard Rule)
For every important finding or section:
- Determine first whether the evidence can be shown visually
- If yes → visual BEFORE text explanation
- If no meaningful visual exists → strong editorial layout

The purpose is: a busy business owner should understand the biggest issue within seconds of opening the section, before reading a word of explanation.

---

## Visual Decision Rules
Match visual type to the story:
- Meaningful numerical data → appropriate chart/comparison visual
- No numerical data, but meaningful qualitative evidence → qualitative visual
- Neither → strong editorial presentation
- NEVER fabricate numbers just to create a graph
- NEVER create arbitrary percentages or fake scores

---

## The Top 5 Rule
- Maximum 5 overall top priorities. Never repeat the same root cause across multiple items.
- If there are only 2 or 3 genuinely important findings, show only those.
- Never create weak findings just to fill space.

---

## Report Length
- Dynamic. Content-driven. Do not force a fixed page count.
- Use expandable "See More Details" sections to preserve research without cluttering the initial view.
- Do not remove meaningful research simply to make the report shorter.

---

## Design Requirements
Client-facing reports must be:
- Visually premium, professional, and human-researched in feel
- Business-owner friendly — NOT a software dashboard or SEO tool
- Responsive and mobile-friendly for web reports
- Eye-catching at first glance

Use:
- Strong visual hierarchy
- Large meaningful metrics where real data supports them
- Short, scannable paragraphs
- Appropriate visual comparisons (charts, comparison bars, qualitative indicators)
- Clear section separation
- White space

Avoid:
- Dense walls of text
- Technical jargon in primary copy
- Decorative charts with no analytical purpose
- Fake percentages or health scores
- Excessive visual noise or repeated card layouts
- Generic dashboardy aesthetic

---

## Approved Report Structure
1. Cover / Hero (business name prominent, Mark Bishop Media brand, NOT an AI dashboard)
2. Local Visibility at a Glance (4 pillar visual status, biggest opportunity, strongest asset)
3. What's Working (strengths FIRST, before weaknesses)
4. Priority Finding Deep Dives (one per finding, visual → explanation → why → recommendation → see more)
5. Competitive Snapshot (conditional — only if validated competitor data exists)
6. Additional Growth Opportunities (conditional — only if secondary findings exist)
7. Recommended Action Roadmap (numbered sequential steps)
8. Mark Bishop Media CTA (single instance, end of report only)

---

## Strengths Before Weaknesses
Always show what the business already has going for it before presenting areas for improvement.

---

## Progressive Disclosure Rule
- Default view: Visual + What We Found + Why This Matters + Recommended Action
- Expandable: Additional evidence, specific named items, technical details
- Never remove useful research — use "See More Details" to preserve depth

## Language Rules
- All technical findings must be translated into plain business language in primary copy
- Technical details belong only in expandable "See More Details" sections
- Prohibited in primary copy: NAP, schema, JSON-LD, GBP, citations, SEO, API, SERP, entity optimization, LLM, AI, Stage 6, queried, scraped
- Prohibited in any client-facing copy: "Our AI found...", "We queried...", "We scraped...", evidence IDs, stage names

---

## Never Invent Data
- No fake percentages
- No invented health scores
- No fabricated revenue impact
- No causal ranking claims
- No ROI projections
- No unsupported performance guarantees
